# 팀 어항 통합 안내

수업 외 내용입니다. 기존 회사 홈페이지와 Vue/PixiJS 어항에 [dongpal0825/aquabit](https://github.com/dongpal0825/aquabit)의 팀 UI·Express/MySQL 기능을 합쳤습니다.
참고한 커밋은 `284c3bbb143adedbb1986a88fbf7c17652d816b4`입니다. 원본 저장소에 변경 사항을 업로드하지 않았습니다.

## 화면과 파일

- 홈페이지 `/` → 게임 시작 → `/community/login.html`
- 로그인·회원가입 → `/community/tanks.html` (만들기·초대 코드로 참여)
- 팀 어항 `/community/tank.html?id=...`: 프로필, 진주·먹이, 채팅, 꾸미기, 과제, 상점, 팀 관리
- `public/community/`: 원본 저장소에서 가져와 통합한 HTML·CSS·메뉴 코드
- `game/community-entry.js`: 팀 데이터와 기존 Vue/PixiJS 렌더러를 연결하는 변환 계층
- `game/public/assets/`: 직접 수정하는 PNG 원본. 이미지 파일을 교체하거나 덮어쓰지 않았습니다.
- `server/game/`: 회원·어항·물고기·과제·상점·팀 채팅용 MySQL API
- `sql/community-schema.sql`: 기존 테이블을 삭제하지 않는 스키마
- 기존 `/play/` 체험 어항도 보존했습니다. 기존 브라우저의 꾸미기 데이터는 덮어쓰지 않습니다.

원본의 글자 지도 물고기와 Canvas 배경 대신 PNG·Vue/PixiJS를 사용합니다. 미리보기·꾸미기·팀 목록도 같은 PNG입니다. 기본 색은 원본이고 다른 색은 화면 효과로 적용합니다. 종류는 금붕어·구피·베타·네온테트라·새우·엔젤피쉬·불가사리입니다. 새우를 제외한 6종은 새로 만든 **64×40 두 프레임**이며, 새우는 사용자 요청으로 마지막에 첨부한 파란 새우 그림을 직접 분리한 96×64 두 프레임을 사용합니다. 불가사리는 바닥을 천천히 이동합니다. 파일은 `game/public/assets/creatures/`, 연결 정보는 `game/domain/creatures.json`입니다. 예전 종류 값은 새 종류로 연결하므로 저장된 계정·물고기 이름·경험치는 삭제하지 않습니다. 이전 이미지 백업은 `artwork/history/2026-11-20-before-seven-species/`에 있습니다.

외형 진화와 크기 증가는 제거했습니다. 먹이를 받으면 레벨이 오르며, 리본 Lv.2 / 꽃 Lv.3 / 왕관 Lv.4에 착용이 열립니다. 상점에서 산 장식도 레벨 조건을 만족해야 착용할 수 있습니다. 원본 서버의 `hat` 아이템 키는 호환을 위해 유지하되 화면과 PNG는 꽃으로 표시합니다. 내 물고기에게만 먹이를 줄 수 있습니다. 저장소의 하루 급식 한도 5회는 유지합니다. 새 계정은 먹이 10개를 받습니다.

오늘 급식 한도를 채우면 `배불러요`, 재고가 없으면 `먹이가 부족해요`를 표시합니다. 먹이 버튼·물고기 카드·드래그 먹이통 모두 같은 기준을 사용하며, 막힌 급식은 재고를 차감하거나 알갱이를 생성하지 않습니다. 여러 알을 요청해도 남은 한도·재고만큼만 소비합니다. 어항 설정은 하단 **어항** 메뉴에 있고, 왼쪽 우체통은 사내 메일, 오른쪽 말풍선은 팀 채팅입니다. 아이콘 PNG는 `icon-mailbox.png`, `icon-chat.png`입니다.

더블클릭은 오른쪽 팀 채팅을 열고, 사내 메일은 별도 편지 버튼으로 기존 웹메일 창을 엽니다. 편지 창의 채팅 탭도 현재 팀의 같은 대화에 연결됩니다. 설정에서 수초·산호·수목, 기포·햇살·빛 색상·세기와 움직임 멈추기를 조절합니다. 물고기 꾸미기의 컬러 슬라이더는 원본 PNG를 수정하지 않고 화면에 적용하며 MySQL의 `fish.hue`에 저장합니다. 메일 설정은 변경하지 않습니다. 메일 탭만 열어서는 실제 메일 서버에 접속하지 않습니다.

## 노트북에서 DB 없이 확인

```bash
npm install
npm start
```

게임 시작 → **체험하기**를 누르세요. 체험에서는 이 브라우저의 별도 저장소를 사용합니다. 꾸미기·급식·상점·과제 등록·어항 목록을 확인할 수 있습니다. 다른 PC와 공유되지 않으며 실제 회원가입이나 사내 메일을 흉내 내지 않습니다. 다른 팀원의 과제 제출·승인과 대표 이전 등은 실제 계정 모드에서 사용합니다. 로그아웃하면 체험 모드에서 나옵니다.

## Rocky Linux 10에서 MySQL 연결

MySQL에 `aquabit` 데이터베이스와 앱용 DB 계정이 준비된 상태에서 진행합니다. 기존 `.env`의 홈페이지·메일 설정은 유지하고 아래 항목만 채웁니다. 비밀번호나 세션 키는 문서·Git·채팅에 공유하지 마세요.

```dotenv
GAME_URL=/community/login.html
GAME_DATABASE_ENABLED=true
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=aquabit
DB_USER=aquabit
DB_PASSWORD=
SESSION_SECRET=
```

`DB_PASSWORD`와 `SESSION_SECRET`은 서버의 `.env`에서 직접 설정합니다. DB 준비 후 다음을 실행합니다.

```bash
npm run db:game:init
npm start
```

초기화 명령은 기존 테이블·데이터를 삭제하지 않습니다. 기존 저장소와 호환되도록 물고기의 종류·색 ENUM을 확장합니다. 원본의 seed·관리자 생성·테이블 삭제 스크립트는 포함하지 않았습니다. 실제 MySQL 연결·계정 간 공유·Socket.IO는 아직 검증하지 않았으며 실습 DB를 준비한 뒤 확인해야 합니다. DB 기능을 켜지 않으면 MySQL로 접속하지 않습니다.

현재 홈페이지처럼 Apache가 `/` 전체를 Node.js로 프록시하면 새 경로도 함께 전달됩니다. Socket.IO를 사용할 때는 `/game-socket.io/`의 WebSocket 전달이 추가로 필요합니다. 연결되지 않으면 팀 데이터·채팅은 폴링으로 갱신합니다. 사내 메일과 게임 계정은 별도 인증입니다.

기존 게임의 브라우저 저장 데이터와 MySQL 계정 데이터는 자동으로 합치지 않습니다. 원본 저장소의 팀 구조는 **어항마다 계정당 1마리**입니다. 체험 데이터는 실제 계정에 자동으로 업로드되지 않습니다.
